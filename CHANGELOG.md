# Changelog

All notable changes are listed here, newest first.

It stays hidden without a URL and tracks outbound clicks; venue enquiries and bookings remain on the partner’s own site.

- **Hub landing-page redesign:** buyer-focused hero, searchable six-person discovery, compact sport collections with role links, cross-sport event formats, booking steps, FAQs and a general enquiry form that prepares an email draft. Mobile navigation works; headings use Recoleta Medium and portraits have editorial focal points. The original partner sites and their gates remain unchanged.

- **Documentation review:** identify the connected `getapeptalk/peptalk-appearances` repository and live Vercel URL, distinguish the older Railway hostname, record dated health checks, and clarify canonical origins, CI job checks, rollback limits, content validation and the local admin CSP.

- **The PepTalk landing page is the home again:** `/` on the hub serves the landing page, which links all eight sites (every active club, league and association), their talent-type rosters and the Terms and Privacy pages. `/all` answers `301` to `/`, keeping the query string. It is prerendered at `/` (`app/(landing)/page.tsx`) with canonical `/`, and sitemaps, `llms.txt`, structured data (`WebSite`, `CollectionPage`) and the hub breadcrumbs use `/`. `registry.json → rootSite` is now optional and removed from the live registry; setting it brings back the old behaviour (`/` redirects to that site, the landing page at `/all`). The landing page still needs the master password, and a visitor who sends a site password there is redirected to their own site instead of being refused. Partner domains are unchanged: `/` is the site's home there. In the admin, *Make root* has a **Landing page (no root site)** option, the dashboard shows which root is active, and the preview of `/` is the landing page.
- **Spurs links restored on the Vercel site:** the Spurs homepage and Sandro profile are no longer look-only demos (`demoHome` / `demoProfiles` removed), so every internal link, form and control works. The Railway demo is unchanged. Demo mode stays available per site and is covered by the test fixtures.

The move to Next.js on Vercel, and everything a developer needs to take the sites over and plug in a CMS.

### Added

- **Next.js app on Vercel.** Every page renders through Next.js 16.4 (App Router, React 19.3, strict TypeScript) from one shared set of React Server Components and is prerendered at build time ([docs/nextjs-migration.md](docs/nextjs-migration.md)). `proxy.ts` handles host routing, the password gate, redirects, security headers and the CSP; `/<slug>/site.css` and `/landing.css` are route handlers. CI runs typecheck, lint, content validation, the contract check, markdown links, tests and `next build`.
- **Developer onboarding** ([docs/onboarding.md](docs/onboarding.md)): setup, an architecture tour, plugging in a CMS, Airtable, the first deploy, launch checklists, open decisions and a glossary.
- **Component gallery** at `/_gallery`: every component in `components/site/` rendered with each site's content and branding (header, hero, cards, the enquiry form in its idle, error and sent states, profile sections, footer, consent banner and more), with a site switcher. Master password only, always `noindex`, prerendered, and out of sitemaps, `llms.txt` and the link checks. `test/next/gallery.test.ts` fails when a component has no gallery entry. Home and profile sections, the header, the footer and the badges became exported components for it; every page renders byte for byte as before.
- **Content layer and contract.** Providers behind one interface (`lib/content/`: JSON, in-memory, a CMS stub), typed `ContentError`s instead of raw exceptions or empty results, and the content contract: JSON Schema for every shape (`schema/`, generated by `npm run schema` from `lib/content/contract/schemas.ts` and tied to `lib/content/types.ts` by the typecheck), valid examples in `schema/examples/`, and a generated field reference in [docs/content-contract.md](docs/content-contract.md).
- **Provider conformance suite** (`test/contract/provider-conformance.ts`): shapes, content rules, publishing switches, slugs, image references, legal content, ordering and typed errors, against the JSON provider, the in-memory provider and the Airtable sync on fixtures. `npm run contract` runs it against a real CMS or Airtable base.
- **Airtable people sync**, ready to switch on with `PEOPLE_PROVIDER=airtable` ([docs/airtable-cms.md](docs/airtable-cms.md)): fields mapped by ID, a publishing gate, stable R2 images only, every record validated (bad ones skipped and reported, fail closed past a threshold), one site per Airtable value, a rate-limited client that never logs the token, and an offline dry run (`npm run airtable:dry-run`).
- **On-demand revalidation**, `POST /api/revalidate`: CMS and Airtable webhooks refresh pages by cache tag without a deploy, authenticated by `REVALIDATE_SECRET`, rate limited, with one cache entry per site and the last good page kept if the source is down.
- **Per-site domains** ([docs/domains.md](docs/domains.md)): `registry.json → domains` serves a site at the root of its own domain from a prerendered domain mount, with aliases, canonical URLs and the gate per host. No site has one yet.
- **Enquiry endpoint**, `POST /api/enquiry`: the form works without JavaScript, checks submissions on the server and forwards them to `ENQUIRY_WEBHOOK_URL` when set (unset today: checked and discarded).
- **Tracking slot, off by default:** `site.json → tracking` (GTM, GA4) or `TRACKING_GTM_ID`, one shared external script, an optional consent banner, and Google's hosts in the CSP only for sites with tags.
- **SEO and AEO, switched on per site at launch** with `site.json → indexable`: robots, sitemaps, `llms.txt`, one JSON-LD graph per page, budgeted titles and descriptions, breadcrumbs, a clean heading outline and an "At a glance" summary on profiles. Also `site.json → lang`, `people.json → sameAs`, `registry.json → indexable` for the hub, the `SEARCH_INDEXING=off` kill switch, and previews that never index.
- **Terms and Privacy pages** on every site and the hub, from shared markdown in `src/copy/legal/` (placeholder text until launch), linked from every footer and the enquiry form's consent line.
- **Vercel readiness** ([docs/vercel.md](docs/vercel.md)): every setting and environment variable, previews, the enquiry webhook and a first-deploy checklist. `test/next/env.test.ts` keeps `.env.example` and the docs complete.
- **Performance budgets in CI** (`npm run perf:budget`, network-free) and `npm run perf`; **visual regression check** (`npm run visual`) against a local baseline captured on `main`.
- **Markdown link checker** (`npm run docs:links`, in `npm run check` and CI).
- **Site packs:** a whole site as one zip, from the site tools or the skill, imported in the admin (inactive) or with `npm run import-pack` ([docs/site-packs.md](docs/site-packs.md)).
- **Licence approvals and verification checklists** in the admin (`licences.json`, `verification.json`); alerts only, with `npm run validate -- --strict` as the launch gate.
- **`IMAGE_HOSTS_EXTRA`** for image hosts (an R2 bucket) that may first appear after a deploy.

### Changed

- **Photos are `<img>` elements** through the Next.js image optimizer (responsive WebP, lazy below the fold, a high-priority LCP photo, descriptive alt text) instead of CSS backgrounds. On mobile, LCP fell from 3.0–9.8 s to 0.8–1.5 s and roster transfer from 2.3 MB to under 0.4 MB.
- **Static pages with a static CSP:** `script-src 'self' 'unsafe-inline'` with Trusted Types and SRI, styles `'self'` only ([docs/architecture.md → Rendering and CSP](docs/architecture.md#rendering-and-csp)).
- **Referrer policy** is `strict-origin-when-cross-origin`, so getapeptalk.com sees referrals; other sites see only the origin.
- **The admin** previews pages with the app's own components, and gained a Search & language section (`indexable`, `lang`, `orgType`), `sameAs` in the person editor and an Indexable badge.
- **The about page heading** defaults to "About <platform>"; `vocab.aboutTitle` still overrides it.
- **Profile pages** no longer show the "beyond" panel; the homepage, roster and Ways to book keep it.
- **The validator** rejects unknown site and person keys.
- **Documentation** rewritten for the Next.js app on Vercel, checked against the code and for broken links.

### Removed

- **The static generator, its server and Docker image**, and their tests: the Next.js app is the only codebase. Assertions that still apply live in `test/next/`; `npm run visual` replaces the old parity check.
- **Stories:** the homepage section, story pages, their links, wording keys, images and cards. A leftover `stories` key is a validation error.

### Fixed

- A hidden featured person no longer crashes the home page; empty "more people" and "popular hosts" sections are left out; shell sites no longer show broken image tiles.
- The roster: an empty roster shows its message without JavaScript, unknown `?role=`/`?era=` links no longer hide every card, an unknown `?legend=` no longer blanks the enquiry select, and the URL `#fragment` is kept.
- A malformed `PUBLIC_ORIGIN` no longer breaks every page; the 404 page has no canonical URL; legal headings no longer skip levels; the about page's description no longer duplicates the home page's; `/_next/image` is behind the gate.

## 1.0.0 (2026-10-19): standalone repository

Moved out of a private PepTalk monorepo into its own repository. Copy fixes: the landing footer now reads "club, league, association…", and the 404 tagline is "Official sports talent platforms".

- **Structure:**
  - content is JSON (`src/sites/<slug>/{site,people,images}.json`) loaded through `src/sites/index.mjs`, with display order in `registry.json`
  - the renderer is split into `src/render/{html,theme,site,landing,index}.mjs`
  - the server is split into `src/server/{app,index}.mjs`
  - scripts live in `scripts/`
- **Tooling:**
  - Biome (lint and format)
  - `npm run validate` (content validator)
  - unit and content tests alongside the integration suite
  - GitHub Actions CI, including a Docker build
- **Site tools:** `new-site` (shell sites with placeholder people and photos) and `assemble-site` (populated sites from research output).
- **Docs and agents:** architecture, adding a site, content model, research brief, deployment, brand and legal, Airtable CMS plan, and a `/new-appearances-site` Claude Code command.
- **Page management:** sites can be switched off (`active`), optional pages hidden (`pages`), and people or stories hidden (`active`). The validator guards every reference.
- **Admin:** `npm run admin`, a local content admin (loopback-bound by default, optional password). It manages sites (create, activate, order, root), page switches, people, stories, wording and theme, and validates before every save. Saves go to the local checkout, or to a GitHub branch and PR.
- **Hardening:**
  - attribute values are escaped
  - the root redirect keeps the query string
  - card redirects work with hyphenated slugs
  - HSTS and Content-Length headers
  - graceful shutdown with a timeout
  - `npm run dev` rebuilds on change
  - `.env` is loaded
  - the site tools print usage and refuse accidental overwrites
- **Renamed:**
  - the per-site stylesheet is now `/<slug>/site.css`
  - the body class is `site-<slug>`
  - `clubName` is now `orgName`
  - FAQ overrides are keyed by stable ids instead of question text
